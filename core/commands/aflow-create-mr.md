# `/aflow-create-mr` — Create Merge Request

Pushes the feature branch and opens an MR per `config.mr.policy`. Runs `config.mr.pre_push` commands before push; aborts on any failure.

## Usage

```
/aflow-create-mr DEV-XXXX
```

## Steps

### 1. Load config + run artifacts

1. Read `.alea.yaml`; validate.
2. Read `.pipeline/runs/<ticket_id>/analysis.json` for title + description.
3. Read every `<layer>_impl.md` (feature) or `implementation.md` (bugfix) for `files_changed` and per-phase summaries.
4. Read `final_report.json` (feature) or `gate_report.json` (bugfix). Verify `passed: true`.

### 2. Verify branch state

```bash
git status
git rev-parse --abbrev-ref HEAD
```

Branch name MUST match `config.mr.branch_pattern` with `{ticket_id}` substituted (and a `{slug}` from the title). If not on the right branch:
```
Error: current branch <X> doesn't match expected pattern <pattern>.
Expected: <substituted branch name>
```
Stop. Do not auto-create the branch — the consumer's git workflow may have specifics.

### 3. Stage changes

For feature runs: stage the union of `files_changed` from every `<layer>_impl.md`.
For bugfix runs: stage `files_changed` from `implementation.md`.

```bash
git add <each file>
```

NEVER `git add .` or `git add -A` — limits the commit to declared files only.

### 4. Run pre_push validations

For each command in `config.mr.pre_push`:

```bash
<command>
```

Abort on the first non-zero exit. Report which step failed and stop. Common steps in the default the reference consumer config: `dart format .`, `dart analyze`, `flutter test`.

### 5. Commit per MR policy

Branch in on `config.mr.policy`:

- `single-commit-amend` — if HEAD's commit message matches the expected MR title, `git commit --amend --no-edit` (after staging). Otherwise create a fresh commit. Then `git push --force-with-lease`.
- `single-commit-squash` — squash every commit since the branch diverged from the
  base branch into one, then push:
  ```bash
  BASE=$(git merge-base HEAD origin/<base_branch>)
  git reset --soft "$BASE"
  git commit -m "<title>"   # message per the Commit message block below
  git push --force-with-lease
  ```
  Use `--force-with-lease` (never plain `--force`) so a teammate's push is never clobbered.
- `multi-commit` — `git commit -m "<title>"` (no force-push).
- `custom` — abort; consumer must extend this command.

Commit message:
```
<analysis.json::title>

<one paragraph from feature_description or bug_description>

Refs: <ticket_id>
```

### 6. Push

```bash
git push <origin> <branch> [--force-with-lease only for amend/squash policies]
```

### 7. Open the MR

Use the consumer's MR platform (GitHub PR / GitLab MR / Bitbucket PR). Detect from `git remote get-url origin`:

- `github.com` → `gh pr create` (requires GitHub CLI).
- `gitlab.com` / self-hosted GitLab → `glab mr create`.
- Other → report the push and stop; consumer opens the MR manually.

MR body:

```markdown
## Summary
<feature_description or bug_description>

## Type
<feature | bugfix>

## Phases completed
<!-- Check [x] ONLY from run artifacts — never pre-checked. A fabricated [x]
     in the MR is asserted-not-earned. Leave [ ] (+ note) if unconfirmed. -->
- [<x if analysis.json>] Analysis
- [<x if spec.json approved>] Design (for feature)
- [<x per <layer>_impl.md present>] Implementation: <list of layers + counts>
- [<x iff every gate_*.json passed>] Gates
- [<x iff final_report.json::passed>] Review: <N>/<N> criteria met
- [<x iff validation_report.json::overall_passed>] Functional validation: <N> covered

## Success criteria
<!-- [x] only if the criterion's asserting test passed in validation_report. -->
- [ ] <criterion 1>

## QA handoff
See [QA handoff document](./aflow-pipeline/runs/<ticket_id>/qa_handoff.md) (generated by `/aflow-qa-handoff`).

## Ticket
<ticket_id> — <raw_url from analysis.json::ticket_source.raw_url>
```

### 7.5. Persist the MR URL

**Persist the MR URL.** Write the returned MR/PR URL into the run report so QA-handoff and merge can verify it: set `final_report.json::mr_url` (feature) or `gate_report.json::mr_url` (bugfix) to the URL. If the report file is missing, create a minimal `{ "mr_url": "<url>" }` so downstream readers still find it.

### 8. Display summary

```
══════════════════════════════════════════════
MR Created: <ticket_id>
══════════════════════════════════════════════
Branch:       <branch>
Commit:       <hash> — <title>
Pre-push:     <N> commands passed
MR URL:       <url>
══════════════════════════════════════════════

Next: /aflow-qa-handoff <ticket_id>
```

## What this command MUST NOT do

- ❌ Skip pre_push commands. They're enforced.
- ❌ Push to `main` or `master` directly.
- ❌ `git add .` or auto-stage unrelated files.
- ❌ Force-push when `config.mr.policy: multi-commit`.
